# As Prescribed: architecture

Prose around the decisions: how the parts work together. The decisions are the ADRs in
[`adr/`](adr/README.md), rendered from the Atlas model; where this document and an ADR differ, the
ADR wins. Module ids are the Atlas model's (`ap.*`).

## 0. Overview

One Python process (FastAPI, `ap.api`) serves the therapist's desk and the patient sheet (`ap.ui`)
and runs one session at a time through the pipeline (`ap.pipeline`). Two OpenAI-compatible
endpoints do the model work (`ap.llm`): a **generator** (Qwen3.5-35B-A3B on the R9700) and a
**falsifier** of another family (gemma-3-12b-it on the 7900 XT) (adr.ap.002). Everything that can
be decided without a model is decided by code.

## 1. The pipeline (one session)

1. **Ingest** (`ap.ingest`): the transcript as spans `{span_id, speaker, ts, text}`, replayed in
   chunks in visit time.
2. **Extract** (`ap.extract`): the generator returns the whole item list (prescribed, deferred,
   withdrawn), re-run during the visit as therapist speech arrives. Every number and side of an item
   is checked against the spans it cites.
3. **Program** (`ap.program`): tags from the catalogue (plus "prosthesis on" from the spans), the
   rule check (`ap.rules`, adr.ap.003), completeness (side, dose, frequency), and the English line
   composed from the item and the approved catalogue sentence (adr.ap.008).
4. **Translate** (`ap.translate`): the generator translates the English line only; the dose and
   frequency numbers must appear as digits.
5. **Falsify** (`ap.falsify`): the falsifier checks every item against the whole transcript (typed
   objections, quoted cautions) and back-translates every line before comparing meanings.
6. **Rounds**: the generator corrects the correctable objections; translations with objections are
   redone with the problem as feedback. Stop when nothing correctable remains, after three rounds,
   or at a time budget. One state per line.

## 2. What code decides, and what a model may not undo

- **Restrictions** (adr.ap.003, adr.ap.005): condition × tag × side → block | caution; a block raised
  in any round is kept to the end and the item is never sent for correction.
- **Corrections** (adr.ap.006): a correction that changes the exercise withdraws the item.
- **Falsifier claims** (adr.ap.007): overruled when the cited spans contradict them by a checkable
  rule; cautions are compared by code from the falsifier's quotes.
- **Numbers**: a dose or frequency number the spans lack is an objection before any model; in a
  translation the numbers are compared as digits (Arabic-Indic normalised, the dual as two).

## 3. The served surface (adr.ap.004, adr.ap.010)

`GET /api/sessions/{id}/run` streams one run as server-sent events (`span`, `items`, `stage`,
`queued`, `result`, `failure`, `end`). Modes: **live** (replay plus extraction during the visit;
reports the latency after the last chunk) and **prescription** (the approved slots, optionally one
injection from the evaluation). One model run at a time (a lock: the box has 16 GB of host RAM), a
short cache for identical runs, and recorded runs (`data/recorded/`, written with `AP_RECORD=1` via
`scripts/record.py`) served when no model answers, or always with `AP_REPLAY=1`, labelled as
recorded. There is no free-text input. The patient sheet receives the approved program in the URL
fragment, which the browser never sends to the server.

## 4. Modes and where they run

| Mode | Generator | Falsifier | Where |
|---|---|---|---|
| Local | Qwen3.5-35B-A3B, llama-agent `:8091`, R9700 | gemma-3-12b-it, llama-theta `:8080`, 7900 XT | Somnus box over Tailscale, per `AS-PRESCRIBED-SOMNUS-BOKSI` |
| Public (planned) | from the AMD tokenfactory list | another family from the list | ultragravel Hetzner machine, systemd + nginx; blocked on the tokenfactory key |
| Replay | none | none | the same server with `AP_REPLAY=1`, serving `data/recorded/` |

Configuration is environment only (`.env.example`); the tokenfactory key goes only to URLs under
`TOKENFACTORY_BASE_URL` and is never printed.

## 5. Data

Approved synthetic content in `data/`: `vocabulary.json` (25 tags), `catalog.json` (28 exercises),
`rules.json` (7 conditions, 14 rules), `profiles/P1-P3`, `sessions/S1-S3` (`.slots.json` the
approved prescriptions, `.transcript.jsonl` the dialogues generated by `scripts/write_transcripts.py`,
`.gold.json` the answer keys). Tests check that every dialogue states its slots and that the rule
engine gives every slot its expected state.

## 6. Evaluation (adr.ap.009)

`asprescribed/evaluation.py` and `scripts/eval.py`: 32 injections (18 only a model can catch, 14
the checks and rules catch, the split tested mechanically) and 9 clean runs, from a plan sealed by
its sha256. Detection is read from round 0. Results and raw runs in `eval/`; the pre-registration
and the results in Atlas.
